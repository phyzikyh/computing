4  문제 분해와 패턴 인식

이 장에서는 복잡한 문제를 해결 가능한 작은 단위로 쪼개는 문제 분해(Decomposition)와, 데이터와 프로세스 속에서 규칙성을 발견하는 패턴 인식(Pattern Recognition)의 원리를 학습합니다. 포야(Pólya)의 문제해결 4단계와 무인 매장 결제 시스템, 기상 데이터 분석 시나리오를 통해 분해와 패턴 인식이 파이썬의 함수, 조건문, 반복문으로 전환되는 메커니즘을 완성합니다.

4.1 조지 포야의 문제해결 모델과 컴퓨팅 사고

복잡한 문제와 마주했을 때 대부분의 초심자는 “어디서부터 시작해야 할지” 막막함을 느낍니다. 헝가리의 저명한 수학자 조지 포야(George Pólya)는 그의 고전적 명저 How to Solve It에서 인간이 문제를 해결하는 보편적인 4단계를 제시하였습니다(Pólya 1945년).

  1. 문제 이해 (Understanding the Problem): 주어진 조건과 구해야 하는 미지수가 무엇인지 파악
  2. 계획 수립 (Devising a Plan): 유사한 문제를 풀어본 경험을 활용하고, 문제를 쪼개어 해결 전략 수립
  3. 계획 실행 (Carrying Out the Plan): 수립한 각 단계를 엄밀하게 수행하며 검증
  4. 반성 및 검토 (Looking Back): 도출된 해법이 올바른지 확인하고 다른 문제로 확장 가능한지 검토

이 포야의 문제해결 철학은 현대 컴퓨터과학에서 문제 분해(Decomposition)와 패턴 인식(Pattern Recognition)이라는 컴퓨팅 사고의 핵심 축으로 정교하게 계승되었습니다(Wing 2006년; Guzdial 2015년).

4.2 문제 분해 (Decomposition): 나누어 정복하라

문제 분해(Decomposition)란 거대하고 다루기 힘든 단일 문제를 작고, 독립적이며, 해결 가능한 여러 개의 부분 문제(Sub-problems)로 나누는 과정입니다. 소프트웨어 공학에서는 이를 전통적으로 “분할 정복(Divide and Conquer)” 전략이라 부릅니다(Cormen 기타 2022년).

하향식(Top-Down) 분해와 상향식(Bottom-Up) 분해

문제를 쪼개는 접근 방식에는 크게 두 가지 경로가 있습니다(Abelson 기타 1996년).

비교 항목 하향식 분해 (Top-Down) 상향식 분해 (Bottom-Up)
접근 방향 전체 시스템의 최상위 목표에서 시작하여 세부 단위로 하향 세분화 이미 해결 가능한 작은 기초 부품(모듈)들을 먼저 개발한 후 결합
적용 시점 전체 구조와 비즈니스 요구사항을 처음 기획하고 설계할 때 이미 검증된 라이브러리나 공통 함수 모듈이 충분히 갖추어져 있을 때
핵심 장점 전체적인 조감도(Overview)를 잃지 않고 체계적인 구조화 가능 개별 모듈의 신뢰성을 미리 확보하며 점진적으로 시스템 완성

실전 시나리오: 무인 스마트 스토어 결제 시스템 분해

대학 캠퍼스에 도입된 무인 편의점의 “자동 결제 키오스크 시스템”을 하향식 분해 기법으로 설계해 봅시다.

소프트웨어 모듈화의 핵심 (결합도와 응집도): 잘 분해된 하위 문제는 자기 자신의 기능에 충실(높은 응집도)해야 하며, 다른 하위 모듈의 내부 동작에 불필요하게 간섭하지 않아야(낮은 결합도) 합니다(Dijkstra 1972년).

4.3 패턴 인식 (Pattern Recognition): 규칙성과 유사성의 탐색

패턴 인식(Pattern Recognition)이란 분해된 데이터나 반복되는 프로세스 속에서 공통된 구조, 주기적 변동, 조건부 규칙, 상관관계를 찾아내는 능력입니다(Barr 와/과 Stephenson 2011년).

데이터 패턴의 3가지 유형

  1. 시간적 반복 패턴 (Temporal Patterns): 일정 시간 주기(초, 일, 계절 등)에 따라 동일한 현상이 되풀이되는 형태
  2. 구조적 유사 패턴 (Structural Patterns): 서로 다른 데이터 개체들이 동일한 데이터 형식(속성 목록)을 공유하는 형태
  3. 인과/조건 규칙 패턴 (Rule-based Patterns): “만약 \(A\) 조건이 참이면 \(B\) 처리를 수행한다”는 논리적 규칙

실전 데이터 시나리오: 기상청 주간 강수량 및 미세먼지 분석

다음은 기상청에서 관측된 일주일간의 날씨 데이터입니다. 이 데이터에서 발견할 수 있는 패턴을 분석해 봅시다.

요일 최고기온(°C) 강수확률(%) 미세먼지(㎍/㎥) 우산 필요 여부
월요일 24 10 35 (보통) 불필요
화요일 22 80 18 (좋음) 필요
수요일 19 90 12 (좋음) 필요
목요일 25 20 65 (나쁨) 불필요
금요일 26 30 78 (나쁨) 불필요
토요일 21 70 25 (좋음) 필요
일요일 23 0 40 (보통) 불필요

발견된 패턴과 규칙

  • 패턴 1 (강수와 우산의 규칙): 강수확률이 \(60\%\) 이상인 날(화, 수, 토)에는 반드시 우산이 필요하다.
  • 패턴 2 (강수와 미세먼지의 역상관성): 비가 오는 날에는 대기 정화 작용으로 인해 미세먼지 농도가 \(30\,\mu\text{g/m}^3\) 이하(좋음)로 급감한다.
  • 패턴 3 (데이터 순회의 구조적 반복): 매 요일마다 (강수확률 >= 60) 조건을 검사하는 동일한 논리가 7회 반복된다.

이를 파이썬 코드로 표현하면 다음과 같습니다.

# 1주일간의 강수확률 데이터 (월~일)
rain_probabilities = [10, 80, 90, 20, 30, 70, 0]
days = ["월", "화", "수", "목", "금", "토", "일"]

umbrella_days = []

# 데이터 순회 및 조건 패턴 적용
for i in range(len(rain_probabilities)):
    prob = rain_probabilities[i]
    day = days[i]
    
    # 패턴: 60% 이상이면 우산 준비
    if prob >= 60:
        umbrella_days.append(f"{day}요일({prob}%)")

print("우산이 필요한 요일 목록:", umbrella_days)

요약 및 핵심 정리

  1. 문제 분해(Decomposition)는 거대한 문제를 독립적으로 해결 가능한 작은 하위 단위로 나누는 기법으로, 시스템 설계 시 하향식(Top-Down)과 상향식(Bottom-Up) 접근을 균형 있게 사용합니다.
  2. 잘 분해된 소프트웨어 모듈은 높은 응집도(단일 기능 집중)와 낮은 결합도(상호 의존성 최소화)를 가져야 유지보수가 용이합니다.
  3. 패턴 인식(Pattern Recognition)은 데이터 간의 유사성과 프로세스의 반복 규칙을 탐색하는 과정이며, 이는 파이썬의 반복문(for/while), 조건문(if), 함수(def)의 직접적인 토대가 됩니다.
