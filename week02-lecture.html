5  이론

대학 축제를 준비하는 학생회가 생수 240병을 받았습니다. 운영 부스는 6곳이고, 모든 부스에 같은 수량을 배정해야 합니다. 이 문제는 짧은 나눗셈 하나로 해결할 수 있습니다.

하지만 축제 전체를 준비하는 일은 그렇지 않습니다. 장소 예약, 부스 모집, 안전 관리, 홍보, 물품 구매, 예산 정산이 서로 얽혀 있기 때문입니다. 큰 문제를 그대로 붙잡고 있으면 무엇부터 해야 할지 알기 어렵습니다. 먼저 문제를 작은 단위로 나누고, 작은 문제 사이에서 반복되는 구조를 찾아야 합니다.

5.1 문제와 해결책을 구분하기

“학생식당의 줄이 길다”는 관찰된 현상입니다. “키오스크를 설치하자”는 해결책입니다. 두 문장 사이에는 해결해야 할 문제가 빠져 있습니다.

구분 예시 확인할 내용
현상 점심시간에 줄이 길다 몇 명이 언제 기다리는가?
원인 추정 결제가 느린 것 같다 실제로 결제 단계가 가장 느린가?
문제 평균 대기시간을 줄여야 한다 현재값과 목표값은 얼마인가?
해결책 키오스크를 설치한다 원인을 해결하며 제약조건을 지키는가?

해결책을 먼저 정하면 실제 원인을 놓칠 수 있습니다. 결제가 아니라 조리가 느리다면 키오스크를 추가해도 전체 대기시간은 거의 줄지 않습니다.

문제를 측정 가능한 문장으로 바꾸기

“식당을 편리하게 만들자”는 결과를 확인하기 어렵습니다. 다음처럼 범위와 기준을 넣으면 해결 가능한 문제가 됩니다.

평일 12시부터 13시까지 학생식당의 주문·결제·조리·배식 시간을 측정하여 가장 오래 걸리는 단계를 찾고, 기존 공간과 인력 안에서 평균 대기시간을 15분에서 10분 이하로 줄인다.

이 문장에는 현재 상태, 목표 상태, 필요한 자료와 제약조건이 들어 있습니다.

요소 학생식당 사례
현재 상태 평균 대기시간 15분
목표 상태 평균 대기시간 10분 이하
필요한 자료 주문·결제·조리·배식의 시작과 종료 시각
만들어야 할 결과 가장 느린 단계와 개선안
제약조건 기존 공간과 인력 사용

문제를 명확하게 표현하면 무엇을 조사하고 어떤 결과를 만들어야 하는지 보이기 시작합니다.

5.2 문제 분해

문제 분해(Decomposition)는 복잡한 문제를 해결 가능한 작은 문제로 나누는 과정입니다. 단순히 조각을 많이 만드는 것이 목적은 아닙니다. 각각을 해결한 뒤 다시 결합했을 때 원래 문제의 답이 되어야 합니다.

기능에 따라 나누기

대학 축제 준비를 수행해야 할 기능으로 나눌 수 있습니다.

“장소 예약”과 “안전 관리”는 역할이 다릅니다. 한쪽 결과가 다른 쪽을 대신하지 않습니다. 이렇게 기능이 분명하게 구분되면 담당자를 배정하고 진행 상황을 확인하기 쉬워집니다.

같은 수준으로 나누기

다음 분해는 크기가 서로 맞지 않습니다.

  • 주문 과정 개선
  • 결제 과정 개선
  • 조리 과정 개선
  • 확인 버튼을 파란색으로 변경

앞의 세 항목은 큰 기능이고 마지막 항목은 화면 구성의 세부 사항입니다. 같은 단계에는 비슷한 크기의 문제를 놓아야 합니다.

  • 주문 과정 개선
  • 결제 과정 개선
  • 조리 과정 개선
  • 배식 과정 개선

버튼 색상은 “주문 화면 개선” 아래의 더 작은 문제로 배치할 수 있습니다.

빠진 문제와 겹치는 문제 찾기

좋은 분해에는 중요한 문제가 빠지지 않아야 합니다. 또한 두 하위 문제가 같은 일을 반복해서 다루지 않아야 합니다.

점검 기준 확인 질문
누락 원래 목표를 달성하는 데 필요한 부분이 빠졌는가?
중복 서로 다른 이름으로 같은 일을 다루고 있는가?
크기 한 번에 이해하고 해결할 수 있는가?
결합 결과를 합치면 원래 문제에 답할 수 있는가?

“축제 홍보, 포스터 제작, SNS 게시”를 같은 단계에 두면 중복이 생깁니다. 포스터와 SNS는 모두 홍보 방법이기 때문입니다. 같은 수준에서는 “홍보 대상 분석, 메시지 작성, 매체 선택, 효과 확인”처럼 나누는 편이 적절합니다.

5.3 순차 해결과 병렬 해결

분해된 문제가 모두 독립적인 것은 아닙니다. 앞 작업의 결과가 있어야 다음 작업을 시작할 수 있는 경우가 있습니다.

순차적으로 해결하는 문제

축제 부스를 배치하려면 먼저 참가 신청을 받아야 합니다. 배치가 끝난 뒤에 전기와 안전 시설을 확정할 수 있습니다.

이처럼 앞 단계의 결과가 다음 단계에 필요한 관계를 순차 관계라고 볼 수 있습니다.

동시에 해결할 수 있는 문제

모든 작업을 한 줄로 세울 필요는 없습니다. 장소가 확정된 뒤 홍보물 제작과 물품 수량 계산을 서로 다른 팀이 동시에 진행할 수 있습니다.

병렬로 처리하면 전체 시간을 줄일 수 있지만, 마지막에 어떤 형식으로 결과를 합칠지 미리 정해야 합니다.

작은 결과를 다시 결합하기

생수 배분 문제를 세 부분으로 나눠 봅시다.

  1. 전체 생수 수량을 확인한다.
  2. 운영 부스 수를 확인한다.
  3. 전체 수량을 부스 수로 나눈다.

각 단계의 결과를 결합하면 “부스당 40병”이라는 원래 문제의 답을 얻습니다.

\[ \text{부스당 생수} = \frac{\text{전체 생수}}{\text{부스 수}} = \frac{240}{6} = 40 \]

분해는 작은 문제를 만드는 데서 끝나지 않습니다. 입력 → 처리 → 출력의 연결을 확인해야 합니다.

5.4 패턴 인식

패턴 인식(Pattern Recognition)은 여러 문제나 데이터에서 반복되는 부분과 공통 구조를 찾는 과정입니다. 공통부분을 발견하면 매번 처음부터 해결하지 않고 기존 방법을 재사용할 수 있습니다.

반복되는 계산 구조

다음 문제들은 겉모습이 다릅니다.

  • 생수 240병을 부스 6곳에 똑같이 나눈다.
  • 학생 36명을 모둠 6개로 나눈다.
  • 예산 900,000원을 팀 9개에 동일하게 배정한다.

하지만 계산 구조는 같습니다.

\[ \text{한 단위의 양} = \frac{\text{전체 양}}{\text{단위 개수}} \]

이 공통 구조를 발견하면 새로운 배분 문제에도 같은 해결 방법을 적용할 수 있습니다.

전체 양 단위 개수 한 단위의 양
생수 240병 부스 6곳 40병
학생 36명 모둠 6개 6명
예산 900,000원 팀 9개 100,000원

바뀌는 부분과 반복되는 부분

패턴을 찾을 때는 두 부분을 구분합니다.

  • 바뀌는 부분: 생수 수량, 학생 수, 예산, 단위 개수
  • 반복되는 부분: 전체 양을 단위 개수로 나누는 계산

컴퓨터 프로그램에서는 바뀌는 값을 변수에 저장하고, 반복되는 해결 방법은 계산식으로 표현할 수 있습니다.

패턴이 항상 맞는지 확인하기

모든 배분 문제에 나눗셈 하나만 적용할 수 있는 것은 아닙니다. 생수 242병을 부스 6곳에 나누면 2병이 남습니다. 사람을 6.5명씩 배정할 수도 없습니다.

패턴을 사용할 때는 다음을 함께 확인해야 합니다.

  • 나누어떨어지는가?
  • 남는 수량을 어떻게 처리할 것인가?
  • 모든 단위에 반드시 같은 양을 주어야 하는가?
  • 특정 단위에 더 많이 배정해야 하는 조건은 없는가?

패턴은 문제를 단순하게 만들지만, 문제의 조건을 무시하게 만드는 만능 공식은 아닙니다.

5.5 파이썬으로 해결 방법 표현하기

파이썬은 사람이 작성한 명령을 컴퓨터가 실행하도록 표현하는 프로그래밍 언어입니다. 비교적 간결한 문법을 사용하고, 계산·자동화·데이터 분석·인공지능 등 다양한 분야에 활용됩니다.

코드를 작성하면 파이썬 인터프리터가 명령을 위에서 아래로 읽으며 실행합니다.

첫 번째 출력

print()는 괄호 안의 값을 화면에 출력합니다.

print("컴퓨팅 사고 수업을 시작합니다.")
print(2026)
print(3 + 4)

실행 결과는 다음과 같습니다.

컴퓨팅 사고 수업을 시작합니다.
2026
7

"컴퓨팅 사고 수업을 시작합니다."는 문자열입니다. 문자열은 따옴표로 감쌉니다. 2026은 숫자이므로 따옴표를 사용하지 않습니다. 3 + 4는 계산식이므로 계산 결과인 7이 출력됩니다.

print("3 + 4")
print(3 + 4)

첫 줄은 글자 그대로 3 + 4를 출력하고, 둘째 줄은 실제 계산 결과를 출력합니다.

프로그램의 실행 순서

파이썬은 기본적으로 첫 줄부터 마지막 줄까지 순서대로 실행합니다.

print("1. 전체 생수 수량을 확인합니다.")
print("2. 운영 부스 수를 확인합니다.")
print("3. 부스당 수량을 계산합니다.")
print("4. 결과를 출력합니다.")

순서를 바꾸면 의미가 달라질 수 있습니다. 계산에 필요한 값을 확인하기 전에 결과를 계산할 수는 없습니다.

5.6 변수로 바뀌는 값 저장하기

변수는 프로그램에서 사용할 값에 이름을 붙인 것입니다.

water_count = 240
booth_count = 6

print(water_count)
print(booth_count)

등호 =는 수학의 “같다”와 조금 다릅니다. 오른쪽 값을 왼쪽 변수에 저장하라는 뜻입니다.

water_count = 240

위 문장은 숫자 240을 water_count라는 이름으로 저장합니다.

의미가 드러나는 변수 이름

a = 240
b = 6
c = a / b

코드는 실행되지만 각 값의 의미를 알기 어렵습니다.

water_count = 240
booth_count = 6
water_per_booth = water_count / booth_count

변수 이름만 읽어도 전체 생수, 부스 수, 부스당 생수라는 의미를 파악할 수 있습니다. 여러 단어를 연결할 때 밑줄을 사용하는 방식을 스네이크 케이스라고 합니다.

변수값 변경하기

변수에는 새로운 값을 다시 저장할 수 있습니다.

booth_count = 6
print("처음 부스 수:", booth_count)

booth_count = 8
print("변경된 부스 수:", booth_count)

실행 결과:

처음 부스 수: 6
변경된 부스 수: 8

두 번째 저장이 실행되면 booth_count가 가리키는 값은 8로 바뀝니다.

5.7 분해한 계산을 코드로 결합하기

생수 배분 문제를 파이썬 코드로 표현해 봅시다.

# 입력에 해당하는 값
water_count = 240
booth_count = 6

# 처리: 부스당 생수 계산
water_per_booth = water_count / booth_count

# 출력
print("전체 생수:", water_count)
print("운영 부스:", booth_count)
print("부스당 생수:", water_per_booth)

실행 결과:

전체 생수: 240
운영 부스: 6
부스당 생수: 40.0

코드에서도 문제를 세 부분으로 나눌 수 있습니다.

부분 코드 역할
입력 water_count, booth_count 계산에 필요한 값 준비
처리 water_count / booth_count 문제의 계산 수행
출력 print() 계산 결과 확인

# 뒤의 문장은 주석입니다. 주석은 코드의 의미를 사람에게 설명하며 파이썬은 실행하지 않습니다.

값이 달라져도 같은 패턴 사용하기

student_count = 36
team_count = 6
students_per_team = student_count / team_count
print("모둠당 학생 수:", students_per_team)

budget = 900000
club_count = 9
budget_per_club = budget / club_count
print("동아리당 예산:", budget_per_club)

다루는 대상은 학생과 예산으로 다르지만 “전체를 개수로 나눈다”는 해결 패턴은 같습니다.

5.8 반복되는 코드에서 패턴 찾기

print("월요일 대기시간:", 14)
print("화요일 대기시간:", 12)
print("수요일 대기시간:", 15)

세 줄에서 바뀌는 부분은 요일과 숫자입니다. print()로 요일과 대기시간을 출력하는 구조는 반복됩니다.

데이터가 3일이면 직접 작성할 수 있지만 365일이라면 같은 코드를 반복해서 쓰기 어렵습니다. 반복되는 구조를 발견하는 것은 자동화할 부분을 찾는 첫 단계입니다.

5.9 오류는 수정할 위치를 알려 주는 정보다

처음 코드를 작성하면 오류가 자주 발생합니다. 오류 메시지는 실패 선언이 아니라 파이썬이 발견한 문제의 위치와 종류를 알려 주는 정보입니다.

따옴표가 닫히지 않은 경우

print("축제를 시작합니다.)

문자열을 시작한 큰따옴표가 닫히지 않았습니다. 파이썬은 코드 구조를 해석할 수 없어 SyntaxError를 발생시킵니다.

print("축제를 시작합니다.")

변수 이름이 다른 경우

student_count = 42
print(students_count)

저장한 변수는 student_count이지만 출력할 때는 students_count라고 작성했습니다. 파이썬은 정의되지 않은 이름을 발견하면 NameError를 발생시킵니다.

student_count = 42
print(student_count)

오류를 확인하는 순서

  1. 오류 메시지의 마지막 줄에서 오류 종류를 확인합니다.
  2. 오류가 발생했다고 표시된 줄을 확인합니다.
  3. 괄호, 따옴표, 변수 이름을 먼저 비교합니다.
  4. 한 부분만 수정한 뒤 다시 실행합니다.
  5. 예상 결과와 실제 결과를 비교합니다.

한꺼번에 여러 곳을 바꾸면 어떤 수정이 문제를 해결했는지 알기 어렵습니다.

5.10 하나의 문제를 끝까지 표현하기

동아리 연합행사에서 간식 315개를 7개 동아리에 같은 수량으로 배분하려고 합니다.

문제를 작은 부분으로 나누기

  1. 전체 간식 수를 확인한다.
  2. 참가 동아리 수를 확인한다.
  3. 전체 간식을 동아리 수로 나눈다.
  4. 동아리당 수량을 출력한다.

반복되는 해결 패턴 찾기

생수 배분, 학생 모둠 편성, 예산 분배와 같은 “전체 ÷ 단위 수” 구조입니다.

파이썬 코드

# 행사 간식 배분
snack_count = 315
club_count = 7

snacks_per_club = snack_count / club_count

print("전체 간식:", snack_count)
print("참가 동아리:", club_count)
print("동아리당 간식:", snacks_per_club)

다른 값으로 확인하기

간식이 320개라면 결과는 정수로 나누어떨어지지 않습니다.

snack_count = 320
club_count = 7
snacks_per_club = snack_count / club_count
print(snacks_per_club)

결과는 약 45.714285...입니다. 실제 간식을 소수로 나눌 수는 없습니다. 이 경우 각 동아리에 45개씩 주고 남는 간식을 별도로 처리해야 합니다. 문제의 조건이 달라지면 필요한 계산도 달라집니다.

문제 분해는 코드를 여러 줄로 만드는 기술이 아닙니다. 무엇을 입력으로 받고, 어떤 계산을 수행하며, 어떤 결과를 만들어야 하는지 구분하는 사고 과정입니다. 패턴 인식은 여러 문제에서 공통으로 사용할 수 있는 해결 구조를 찾는 과정입니다. 파이썬은 그 해결 구조를 컴퓨터가 실행할 수 있도록 정확한 명령으로 표현하는 도구입니다.
