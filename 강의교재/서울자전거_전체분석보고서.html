Part 1 - 문제 정의와 탐색적 데이터 분석(EDA)

1-1. 무엇을 예측할까요?

기온만 사용했을 때와 시간대, 강수량, 습도를 차례로 추가했을 때의 예측 오차를 비교합니다.

구분 내용
정답 실제 대여 건수
대상 자전거를 운영한 시간의 기록
입력 후보 기온, 시간대, 강수량, 습도
평가 실제값과 예측값의 평균적인 차이

분석은 학습 자료에서 특징 관찰 → 입력 후보와 모델 결정 → 코드에 반영 → 평가 결과 확인 순서로 진행합니다. 모든 모델과 입력 조합을 평가 전에 정하고, 평가 결과를 보고 설정을 반복해서 바꾸지 않습니다.

1-2. 도구와 데이터 불러오기

pandas는 표를 다룹니다. 세 모델은 입력과 정답의 관계를 학습하고, mean_absolute_error는 예측 오차를 계산합니다.

Python - 1
import pandas as pd
from sklearn.linear_model import LinearRegression
from sklearn.tree import DecisionTreeRegressor
from sklearn.ensemble import RandomForestRegressor
from sklearn.metrics import mean_absolute_error

코드 사용법과 결과 읽기

  • import pandas as pd는 pandas를 불러와 pd라는 짧은 이름으로 사용합니다.
  • from 도구 import 이름은 필요한 모델이나 함수를 가져옵니다. 이 단계에서 모델이 학습되는 것은 아닙니다.
  • LinearRegression은 선형 회귀, DecisionTreeRegressor는 회귀나무, RandomForestRegressor는 여러 회귀나무의 예측을 평균하는 모델입니다.
  • mean_absolute_error(실제값, 예측값)은 평균 절대 오차를 숫자 하나로 반환합니다.

1-3. 관계를 찾을 자료와 평가할 자료 구분하기

운영하지 않은 시간과 운영했지만 이용량이 적은 시간은 구분해야 합니다. 운영한 시간의 수요를 예측하므로 Yes인 기록을 선택합니다.

앞선 기간을 학습 자료, 뒤 기간을 평가 자료로 나눕니다. EDA에서는 학습 자료의 복사본인 explore만 살펴봅니다. 평가 자료의 정답을 보며 입력을 고르면 이미 본 답에 맞춘 선택이 될 수 있기 때문입니다. 학습에 쓰지 않은 뒤 기간에서 오차를 확인해야 새로운 기록에도 적용되는지 판단할 수 있습니다.

Python - 5
operating = bike[bike["functioning_day"] == "Yes"].copy()
train = operating[operating["date"] < "2018-09-01"].copy()
test = operating[operating["date"] >= "2018-09-01"].copy()
explore = train.copy()
print("학습 기록 수:", len(train))
print("평가 기록 수:", len(test))
실제 실행 결과
학습 기록 수: 6528
평가 기록 수: 1937

코드 사용법과 결과 읽기

  • == "Yes"는 각 행의 운영 여부를 참 또는 거짓으로 표시하는 조건입니다.
  • 표[조건]은 조건이 참인 행만 담은 데이터프레임을 반환합니다. copy()는 그 표의 복사본을 만듭니다.
  • <는 기준 날짜 이전, >=는 기준 날짜와 같거나 이후입니다. 같은 날짜의 기록이 두 묶음에 섞이지 않습니다.
  • len(표)는 행 수를 반환합니다. 학습은 6,528행, 평가는 1,937행입니다.
  • explore는 학습 표의 복사본입니다. 탐색용 열을 추가해도 원래 학습 표는 바뀌지 않습니다.

1-4. 대여량을 대표값 하나로 설명할 수 있을까요?

평균과 중앙값, 최댓값을 함께 읽습니다. 큰 값이 평균에 영향을 줄 수 있으므로 한 숫자만 보고 모든 시간이 비슷하다고 판단하지 않습니다.

Python - 6
display(explore["rented_count"].describe())
print("평균:", explore["rented_count"].mean())
print("중앙값:", explore["rented_count"].median())

코드 사용법과 반환값

  • explore["rented_count"]는 대여 건수 열 하나를 시리즈 형태로 고릅니다.
  • .describe()는 개수, 평균, 표준편차, 최솟값, 사분위수, 최댓값이 담긴 요약 열을 반환합니다.
  • .mean()은 평균 숫자 하나, .median()은 중앙값 숫자 하나를 반환합니다. 중앙값은 크기순 가운데 값이며 개수가 짝수이면 가운데 두 값의 평균입니다.
  • display()는 요약 통계를, print()는 평균과 중앙값을 표시합니다.

관찰: 평균이 중앙값보다 크고 대여량의 범위가 넓습니다.

반영: 학습 정답의 중앙값을 모든 시간에 똑같이 예측하는 방법을 비교 기준으로 둡니다. 입력을 전혀 보지 않는 이 방법보다 모델들이 덜 틀리는지 뒤에서 확인합니다.

1-5. 기온과 대여량의 상관계수 계산하기

상관계수는 두 숫자가 함께 증가하거나 감소하는 관계를 -1~1 사이의 숫자로 요약합니다. 여기서는 기온이 높은 기록에서 대여량도 많은 경향이 있는지 확인합니다.

상관계수 읽는 방법
양수 한쪽이 클수록 다른 쪽도 큰 경향
음수 한쪽이 클수록 다른 쪽은 작은 경향
0에 가까운 값 일정한 직선으로 설명되는 관계가 약함

절댓값이 1에 가까울수록 직선 관계가 뚜렷합니다. 0에 가깝다고 모든 관계가 없는 것은 아닙니다.

먼저 비교할 숫자 열 두 개를 고른 뒤 corr()를 붙입니다. explore[["temperature", "rented_count"]]는 기온과 대여량을 담은 표이고, .corr()는 이 두 열의 상관계수 표를 계산합니다. 아래 코드는 계산한 표를 temperature_relation에 저장한 뒤 출력합니다.

Python - 7
temperature_relation = explore[["temperature", "rented_count"]].corr()
display(temperature_relation)
실제 실행 결과
temperature rented_count
temperature 1.000000 0.596814
rented_count 0.596814 1.000000

코드 사용법과 결과 읽기

  • [["temperature", "rented_count"]]는 두 열을 데이터프레임으로 선택합니다.
  • corr()는 선택한 숫자 열의 상관계수를 담은 데이터프레임을 반환합니다. 기본 계산은 직선 관계를 요약하는 피어슨 상관계수입니다.
  • 행 이름과 열 이름은 비교한 변수입니다. temperature 행과 rented_count 열이 만나는 칸을 읽으면 됩니다. 반대쪽 칸에도 같은 값이 나옵니다.
  • 대각선의 1은 자기 자신과의 관계입니다. 기온과 대여량의 관계를 확인할 때는 대각선 밖의 값을 읽습니다.
  • 기온과 대여 건수가 만나는 칸은 약 0.60입니다. 학습 기간에는 기온이 높을수록 대여가 많은 경향이 있었습니다. 이 숫자가 정확도 60%라는 뜻은 아닙니다.
  • 상관계수가 높다고 원인이 증명되거나 예측이 정확하다는 뜻은 아닙니다.

반영: 기온 하나를 사용하는 선형 회귀를 첫 모델로 정합니다. 이 모델은 기온이 1℃ 높아질 때 예측값이 일정한 양만큼 달라지는 식을 학습합니다.

1-6. 기온이 비슷해도 시간대별로 다를까요?

기온만으로 충분하다면 비슷한 기온에서 대여량도 비슷할 것입니다. 15℃ 이상 20℃ 미만인 기록을 골라 시간대별 평균을 비교합니다. 다른 조건까지 같게 만든 실험은 아니므로 시간대의 인과 효과를 확인하는 과정은 아닙니다.

Python - 8
mild = explore[(explore["temperature"] >= 15) & (explore["temperature"] < 20)]
mild_by_hour = mild.groupby("hour")["rented_count"].agg(["count", "mean"])
display(mild_by_hour)

  • display()로 평균 열을 보고 print()로 최고 시각을 확인합니다.

관찰: 시각이 커질수록 평균이 일정하게 증가하는 모양은 아닙니다. 아침에 높아졌다 낮아지고 저녁에 다시 높아집니다.

반영: 시각에 일정한 기울기를 곱하는 선형 회귀와, 시간 구간을 조건으로 나눌 수 있는 나무 모델을 모두 비교합니다.

1-7. 비가 오는 기록은 다를까요?

비가 없는 기록과 있는 기록의 개수, 평균 대여량을 비교합니다.

Python - 10
dry = explore[explore["rainfall"] == 0]
rain = explore[explore["rainfall"] > 0]
print("강수 없음:", len(dry), "개, 평균", dry["rented_count"].mean(), "건")
print("강수 있음:", len(rain), "개, 평균", rain["rented_count"].mean(), "건")
실제 실행 결과
강수 없음: 6099 개, 평균 706.736678143958 건
강수 있음: 429 개, 평균 167.65734265734267 건

코드 사용법과 반환값

  • explore["rainfall"] == 0은 강수가 없는 행, > 0은 강수가 있는 행을 찾는 조건입니다.
  • 표[조건]의 결과인 두 표를 각각 dry와 rain에 저장합니다. 이 코드는 원자료를 삭제하지 않습니다.
  • len(dry)와 len(rain)은 각 집단의 행 수, ["rented_count"].mean()은 각 집단의 평균 대여 건수입니다.
  • print(값1, 값2, ...)는 여러 값을 차례로 표시합니다. 집단의 크기와 평균을 함께 읽습니다.

관찰: 비가 있는 기록에서 평균 대여량이 낮습니다. 두 집단의 시간대와 계절 구성까지 같다는 뜻은 아니므로 이 차이를 강수의 인과 효과로 단정하지 않습니다.

반영: 기온과 시간대에 강수량을 추가한 모델을 비교합니다. 집단 비교에서는 강수 유무를 확인했지만 모델에는 원래 강수량 수치를 넣습니다.

  • 상관계수가 작다는 이유만으로 입력에서 바로 제외하지 않습니다. 아래에서는 구간별 평균을 확인하여 직선 하나로 요약하기 어려운 차이도 살펴봅니다.

습도 구간별 평균도 함께 확인하기

습도를 세 구간으로 나누어 대여량의 개수와 평균을 확인합니다. 구간별 평균 차이는 입력 후보로 검토할 근거입니다. 다른 변수와 겹치는 정보일 수도 있으므로 반드시 필요한 변수라고 미리 결론 내리지 않습니다.

Python - 12

humidity_summary = explore.groupby("humidity_group", observed=True)["rented_count"].agg(["count", "mean"])
display(humidity_summary)

코드 사용법과 결과 읽기

  • pd.cut(열, bins=경계값, labels=이름)은 숫자를 구간으로 나눈 범주형 시리즈를 반환합니다.
  • 기본적으로 오른쪽 경계를 포함합니다. 40은 첫 구간, 70은 둘째 구간입니다. include_lowest=True로 최솟값 0도 포함합니다.
  • 구간을 humidity_group이라는 탐색용 열에 저장합니다. 글자로 된 이 구간은 모델 입력으로 사용하지 않습니다.
  • observed=True는 실제 기록이 있는 구간만 집계하라는 뜻입니다.
  • agg(["count", "mean"])로 구간별 개수와 평균을 구합니다. 중간 구간에서 평균이 높고 높은 습도 구간에서 낮아, 단순한 감소 관계만 있는 것은 아닙니다.

반영: 원래 숫자 형태의 습도를 추가 입력 후보로 둡니다. 습도를 제외한 선형 회귀와 포함한 선형 회귀를 비교하여 이 조합에서 오차가 어떻게 달라지는지 확인합니다.

1-9. 관찰한 내용을 분석 계획으로 옮기기

관찰 판단 코드에 반영할 내용
대여량의 평균과 중앙값이 다름 대표값 하나로 설명하기 어려울 수 있음 중앙값 예측을 비교 기준으로 사용
기온과 대여량의 양의 관계 기온을 첫 입력으로 검토 기온 하나의 선형 회귀
비슷한 기온에서도 시간대별 평균이 다름 시간대가 추가 정보를 줄 수 있음 시간대 추가
강수 유무별 평균이 다름 강수량도 입력 후보 강수량 추가
습도 구간별 평균이 다름 습도가 추가 정보를 줄 가능성 습도 포함과 제외 비교
시간대별 평균이 일정하게 증가하지 않음 일정한 기울기의 식에 한계가 있을 수 있음 같은 네 입력으로 나무와 랜덤 포레스트 비교

여기서 변수 선택은 모든 열에서 최적 조합을 찾아낸다는 뜻이 아닙니다. 관찰한 근거가 있는 네 후보로 비교 범위를 정하는 것입니다. 나머지 변수가 쓸모없다고 판단한 것도 아닙니다.

Part 2 - 모델에 사용할 데이터 준비하기

Part 3 - 모델링, 평가, 인사이트 도출

3-1. 중앙값으로 예측하는 기준 만들기

평균 절대 오차(MAE)는 각 기록의 실제값과 예측값 차이에서 부호를 없앤 뒤 평균한 값입니다. 실제값이 100, 200이고 예측값이 80, 230이면 차이의 크기는 20, 30이며 MAE는 25건입니다.

먼저 학습 정답의 중앙값을 모든 시간에 똑같이 답합니다. 입력을 전혀 사용하지 않는 이 방법을 기준으로 둡니다.

Python - 15
middle = y_train.median()
baseline_test_pred = [middle] * len(y_test)
baseline_test_mae = mean_absolute_error(y_test, baseline_test_pred)
print("항상 예측할 값:", middle, "건")
print("중앙값 기준 MAE:", baseline_test_mae, "건")
실제 실행 결과
항상 예측할 값: 424.0 건
중앙값 기준 MAE: 607.6334537945277 건

코드 사용법과 반환값

  • y_train.median()은 학습 정답의 중앙값 하나를 반환합니다. 평가 정답으로 기준값을 만들지 않습니다.
  • [middle] * len(y_test)는 같은 중앙값을 평가 행 수만큼 반복한 리스트입니다. 모든 시간에 같은 값을 예측하는 기준입니다.
  • mean_absolute_error(실제값, 예측값)은 행별 차이의 절댓값을 평균해 숫자 하나를 반환합니다. 실제값과 예측값의 개수, 순서를 맞춰야 합니다.
  • 계산한 오차는 baseline_test_mae에 저장합니다. 여기서는 단위가 건이며, 작을수록 덜 틀렸다는 뜻입니다.

3-2. 기온과의 관계를 첫 모델에 반영하기

기온과 대여량의 양의 관계를 첫 모델로 연결합니다. 선형 회귀는 예측 대여량 = 절편 + 기울기 × 기온 형태의 식을 학습합니다. 실제값과 예측값 차이를 제곱해 더한 값이 작아지도록 계수를 정합니다. 학습의 제곱 오차와 평가의 MAE는 서로 다른 계산입니다.

Python - 16
linear_temp = LinearRegression()
linear_temp.fit(X_train[["temperature"]], y_train)
print("기울기:", linear_temp.coef_[0])
print("절편:", linear_temp.intercept_)
실제 실행 결과
기울기: 28.87520057651711
절편: 311.5448661503258

코드 사용법과 반환값

  • LinearRegression()은 아직 학습하지 않은 선형 회귀 모델을 만듭니다. 그 모델을 linear_temp에 저장합니다.
  • 모델.fit(입력, 정답)은 규칙을 학습하고 학습된 모델 자신을 반환합니다. 예측값 배열을 반환하는 함수는 아닙니다.
  • X_train[["temperature"]]는 열 하나도 표 형태로 고릅니다. 이중 대괄호를 쓰는 이유입니다.
  • 학습 뒤 coef_에는 계수가 배열로 저장됩니다. [0]은 첫 계수입니다. intercept_는 절편입니다. 둘 다 속성이므로 뒤에 ()를 붙이지 않습니다.

fit(입력, 정답)은 관계를 학습하고, predict(입력)은 학습한 관계로 답을 계산합니다. 평가 정답은 예측이 끝난 뒤 비교에만 사용합니다.

Python - 17
temp_test_pred = linear_temp.predict(X_test[["temperature"]])
temp_test_mae = mean_absolute_error(y_test, temp_test_pred)
print("기온 모델 MAE:", temp_test_mae, "건")
실제 실행 결과
기온 모델 MAE: 458.0993974996406 건

코드 사용법과 반환값

  • linear_temp.predict(입력표)는 각 행의 예측값이 담긴 배열을 반환합니다. 평가 입력에도 학습 때와 같은 temperature 열 하나를 줍니다.
  • 반환된 예측을 temp_test_pred에 저장합니다. predict()에는 실제 정답 y_test를 전달하지 않습니다.
  • mean_absolute_error(y_test, temp_test_pred)는 예측을 만든 뒤 정답과 비교해 평균 오차 숫자 하나를 반환합니다.
  • print()로 그 오차를 표시합니다. fit()은 학습, predict()는 예측, 오차 함수는 평가라는 역할 차이를 구분합니다.

3-3. 비슷한 기온에서도 달랐던 시간대 추가하기

15℃ 이상 20℃ 미만에서도 시간대별 대여량이 달랐습니다. 기온만으로 구별하지 못한 차이를 알려 주기 위해 시간대를 추가합니다.

모델 종류와 자료는 유지하고 입력만 늘립니다. 다만 시각을 0~23의 숫자로 넣는 선형 회귀는 시간이 1시간 늘 때 예측값이 일정한 양만큼 변한다고 가정합니다. 아침과 저녁의 두 봉우리를 충분히 표현하는 것은 아닙니다.

linear_time = LinearRegression()
linear_time.fit(X_train[["temperature", "hour"]], y_train)
time_test_pred = linear_time.predict(X_test[["temperature", "hour"]])
time_test_mae = mean_absolute_error(y_test, time_test_pred)
print("시간대 추가 전 MAE:", temp_test_mae)

코드 사용법과 결과 읽기

  • LinearRegression()으로 새로운 모델을 만들고 fit()에 기온과 시간대 두 열을 전달합니다.
  • fit()은 학습을 마친 모델 자신을 반환합니다. 모델 변수에 학습 결과가 저장됩니다.
  • predict()에는 같은 두 열을 같은 순서로 전달합니다. 반환값은 각 행의 예측값이 담긴 배열입니다.
  • MAE는 숫자 하나입니다. 두 출력의 차이는 같은 선형 회귀에서 시간대 입력을 추가한 비교 결과입니다.
  • 차이가 줄어도 시간대의 인과 효과나 모든 미래 기간의 개선이 증명된 것은 아닙니다.

3-6. 시간대의 복잡한 패턴을 나무로 표현하기

시간대별 평균은 아침에 높아졌다가 낮아지고 저녁에 다시 높아졌습니다. 시간에 일정한 계수를 곱하는 방식으로는 이런 굴곡을 충분히 표현하기 어렵습니다.

  • random_state=0은 무작위 선택을 재현하기 위한 설정입니다. 정확도를 0으로 설정하는 뜻이 아닙니다.
  • 입력 네 열과 정답은 앞의 선형 회귀와 같습니다. 이번에는 모델 종류를 바꿨습니다.

  • 같은 마지막 그룹에 들어간 기록은 실제값이 달라도 같은 예측값을 받습니다. 깊이가 제한되면 큰 수요를 충분히 구별하지 못할 수 있습니다.

3-7. 여러 나무의 예측을 평균하기

코드 사용법과 반환값

  • forest.predict(new_data)는 바로 앞에서 만든 같은 입력 표를 랜덤 포레스트에 전달합니다. 입력을 새로 만들거나 다시 학습하지 않습니다.
  • 반환값은 예측 하나가 담긴 배열입니다. forest_new_prediction[0]으로 첫 숫자를 꺼냅니다.
  • print()로 표시한 값을 나무 한 개의 예측과 비교합니다. 같은 조건을 두 방법이 어떻게 계산했는지 보는 것이며 이 입력의 실제 정답이 제공된 것은 아닙니다.

평균을 바탕으로 예측하므로 소수가 나올 수 있습니다. 실제 소수 대의 자전거가 대여된다는 뜻은 아닙니다. MAE를 더하고 빼서 개별 예측의 보장 범위로 해석하지 않습니다.

결론

  1. 학습 자료에서 기온, 시간대, 강수량, 습도와 대여량의 관계를 확인했습니다.
  2. 관찰한 내용을 근거로 입력을 추가한 선형 회귀들을 미리 정했습니다.
  3. 시간대별 굴곡을 표현할 수 있는 나무와 랜덤 포레스트도 같은 네 입력으로 비교했습니다.
  4. 같은 평가 자료에서 오차를 계산하여 입력 추가와 모델 변경의 결과를 구분했습니다.
  5. 큰 오차와 시간대별 오차를 확인해 활용할 때 주의할 조건을 찾았습니다.

EDA의 관찰은 입력과 모델을 검토할 근거입니다. 실제 오차 비교는 그 근거를 예측으로 옮겼을 때 어떤 결과가 나왔는지 확인하는 과정입니다. 변수 선택이 완성되었다거나 인과관계가 증명되었다는 뜻은 아닙니다.

대여소별 위치와 재고 정보가 없어 어느 대여소에 몇 대를 배치할지는 정할 수 없습니다. 관측 날씨로 확인했으므로 실제 사전 예측에는 날씨 예보와 다른 기간에서의 재확인이 필요합니다.

학습 기간의 평균 대여량은 18시에 가장 높았습니다. 미리 정한 기준 방법, 기온 하나의 선형 회귀, 네 입력의 선형 회귀, 의사결정나무, 랜덤 포레스트를 같은 평가 기간에서 비교했습니다.

기온 하나의 선형 회귀 평균 오차는 458.1건입니다. 시간대를 추가하면 386.1건, 강수량까지 추가하면 373.3건, 습도까지 포함하면 346.5건입니다. 이 평가 기간에서는 입력을 추가한 순서대로 오차가 줄었습니다. 습도 구간별 차이를 입력 후보의 근거로 삼고, 포함한 모델과 제외한 모델을 실제 비교한 결과입니다.

같은 네 입력으로 모델을 바꾸면 나무 한 개는 291.2건, 랜덤 포레스트는 266.4건입니다. 시간대별 관계가 일정한 기울기로 변하지 않는다는 관찰을 근거로 나무 모델을 비교했습니다. 다만 나무는 네 입력 모두에서 구간별 관계를 다루므로 이 개선을 시간대 하나의 효과로 해석할 수는 없습니다. 이 비교는 미리 정한 계획의 평가 결과이며, 평가 점수를 보며 최적 변수를 고른 절차는 아닙니다.

평가 1,937개 시간 기록에서 나무의 평균 절대 오차는 291.2건입니다. 학습 중앙값만 반복하는 기준의 607.6건과 비교하면 52.1% 감소했습니다. 이는 미리 정한 모델과 이 평가 기간의 비교 결과이며, 모든 미래 기간의 우위를 보장하지 않습니다. 이 평가 점수를 보고 설정을 반복해서 바꾸지는 않았습니다.
