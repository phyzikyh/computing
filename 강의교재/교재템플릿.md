# 컴퓨팅적사고와논리적문제해결 교재 템플릿

이 문서는 매주 같은 학습 리듬을 유지하기 위한 제작 템플릿이다. 파일 이름과 학생에게 보이는 순서는 `개념 이해(lecture) → 코딩 실습(code) → 학습 점검(quiz)`으로 통일한다.

## 1. 설계 원칙

1. **질문으로 시작한다.** 개념 이름보다 학생이 해결할 현실 문제를 먼저 제시한다.
2. **설명과 활동의 간격을 줄인다.** 긴 이론 뒤에 문제를 몰아두지 않고 2~3개 개념마다 짧은 확인을 둔다.
3. **풀이 과정을 보인다.** 완성 코드만 제시하지 않고 입력·출력·제약조건, 선택한 전략, 실행 결과 해석을 함께 적는다.
4. **난도를 한 단계씩 높인다.** 예측 → 실행 → 수정 → 디버깅 → 독립 구현 → 설명 순으로 진행한다.
5. **오답을 학습 자원으로 쓴다.** 정답뿐 아니라 흔한 오답이 왜 그럴듯하고 왜 틀렸는지 설명한다.
6. **처음의 질문으로 돌아간다.** 주차 끝에서 도달 기준을 확인하고 처음 사례를 해결했는지 점검한다.

## 2. 개념 이해 파일

```markdown
# 개념 이해 {#sec-chX}

::: {.chapter-opening}
[**핵심 질문**]{.essential-question}

> [이번 주 개념으로 해결할 구체적인 질문]

**도달 기준**

- [핵심 개념을 자신의 말로 설명한다.]
- [두 방법을 기준에 따라 구분한다.]
- [새 상황에 해결 절차를 설계한다.]

**학습 경로**  개념 이해 → 코딩 실습 → 학습 점검
:::

[짧은 문제 상황으로 시작하는 도입]

## 개념 1

[개념 설명 → 표/그림 → 짧은 사례]

::: {.checkpoint}
**1분 확인**

[결과 예측·이유 설명·사례 분류 질문]
:::

::: {.worked-example}
**풀이가 보이는 예제**

1. 문제와 제약조건
2. 해결 전략
3. 코드 또는 절차
4. 결과 해석
:::

::: {.misconception}
**자주 하는 착각**

[틀린 생각]이 그럴듯한 이유와 정확한 판단 기준을 함께 설명한다.
:::

## 핵심 정리 {.unnumbered}

- [핵심 문장 3~5개]
- [중요 용어와 판단 기준]

[코딩 실습으로 이동](weekXX_code.qmd)
```

## 3. 빈칸 완성

::: {.transfer}
**새 상황에 적용**

[표면 내용은 다르지만 같은 개념으로 풀 수 있는 문제]

## 4. 학습 점검 파일

문항은 다음 비율을 기본값으로 삼는다.

| 문항 유형 | 권장 비율 | 확인할 능력 |
|---|---:|---|
| 개념·용어 | 20% | 정확한 개념 구분 |
| 실행 결과 예측 | 25% | 코드 추적 |
| 오류 진단 | 25% | 원인 설명과 수정 |
| 새 상황 적용 | 30% | 전이와 문제 해결 |

자동채점 객관식은 모든 선택지에 진단 가치가 있어야 한다. 해설에는 정답 근거, 대표 오답의 원인, 다시 볼 개념을 포함한다. 서술형은 모범답안 전체보다 채점 기준 2~3개를 제공한다.

## 5. 편집 체크리스트

- 핵심 질문과 도달 기준이 본문·실습·점검에 실제로 연결되는가?
- 새 용어는 처음 등장할 때 문맥 안에서 정의했는가?
- 완성 예제와 유사한 연습, 새 맥락의 전이 문제가 모두 있는가?
- 코드 실행 결과를 먼저 예측하게 했는가?
- 정상값·경계값·예외값 중 필요한 테스트를 포함했는가?
- 정리에서 처음의 핵심 질문에 답했는가?
- 링크, 코드, Mermaid, 모바일 화면을 렌더링으로 확인했는가?
