# 코딩 파트 작성 가이드

## 부가적인 안내 문장 금지

코딩 파트 본문에는 다음과 같은 부가적인 설명을 작성하지 않는다.

- 이전 주차에 무엇을 배웠는지 요약하는 문장
- 이번 주차가 이전 주차와 어떻게 다른지 설명하는 문장
- 앞으로 어느 주차에서 특정 문법을 배울지 예고하는 문장
- 이번 주차에서 사용할 수 있거나 사용할 수 없는 문법을 별도 상자나 안내문으로 선언하는 내용
- 강의 구성과 문법 배치 원칙을 학생에게 직접 설명하는 메타 문장

예를 들어 다음과 같은 내용은 코딩 파트에 넣지 않는다.

> 2주차에는 값을 코드에 직접 저장하고 변수와 연산자로 짧은 순차 프로그램을 만들었습니다. 이번 주에는 같은 문법을 처음부터 반복하지 않습니다. 현실 문제에서 필요한 정보만 골라 자연어, 의사코드, 파이썬 코드로 옮기고, 값을 입력받아 재사용하며, 추적과 테스트로 알고리즘을 점검합니다.

> 이번 주 코드는 위에서 아래로 한 번씩 실행되는 순차 구조만 사용합니다. 선택 구조의 `if`는 5주차, 반복 구조의 `for`와 `while`은 6주차에 작성합니다. 순서도에서 그 모양을 배웠더라도 아직 파이썬 문법으로 구현하지 않습니다.

주차 간 중복 방지와 문법 사용 범위는 작성자가 내부적으로 지켜야 할 설계 원칙이다. 학생용 본문에서는 이러한 원칙을 설명하지 않고, 해당 주차에서 다룰 문제 상황·개념·코드·실행 결과·시각화·실습으로 바로 시작한다.

## 코딩실습의 시작 방식

코딩실습은 상황을 꾸며 낸 도입 문단이나 학습 내용을 소개하는 문장으로 시작하지 않는다. 첫 번째 실습 제목, 실행 방법, 코드 중 필요한 항목으로 바로 시작한다.

다음과 같은 도입은 작성하지 않는다.

> 축제 운영 담당자가 방문객 수와 안내소 수를 메모했습니다. 사람은 이 문장을 이해하지만 컴퓨터는 무엇이 글자이고 무엇이 숫자인지 알지 못합니다. 이번 실습에서는 이를 값과 변수로 표현합니다.

코드의 동작, 문법의 의미, 오류 원인, 그림을 읽는 방법처럼 학습에 직접 필요한 설명은 작성한다. 사례를 꾸미는 서사, 주차 간 연결 안내, 작성 의도, 학습 범위 선언처럼 코드를 이해하는 데 직접 필요하지 않은 설명은 작성하지 않는다.

## 제목 번호 작성

Quarto의 자동 절 번호 기능을 사용한다. `##` 이하 제목에 `1.`, `2.`, `3.`과 같은 번호를 직접 입력하지 않는다. 수동 번호를 넣으면 `9.1 1.`처럼 자동 번호와 제목의 번호가 중복된다.

```markdown
<!-- 올바른 작성 -->
## 코드에서 알고리즘 읽기

<!-- 잘못된 작성 -->
## 1. 코드에서 알고리즘 읽기
```
